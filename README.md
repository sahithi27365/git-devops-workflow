# git-devops-workflow





\# Git-Based DevOps Project



\## Overview

This project demonstrates Git and GitHub version-control best practices used in DevOps workflows.



\## Objectives

\- Manage source code using Git.

\- Practice branching and merging.

\- Use pull requests to review changes.

\- Maintain project documentation.

\- Use `.gitignore` to exclude unnecessary files.

\- Use Git tags to mark project versions.



\## Tools Used

\- Git

\- GitHub

\- Markdown



\## Branching Strategy

\- `main`: Stable version of the project.

\- `dev`: Integration branch for changes.

\- `feature/\*`: Branches for individual tasks and improvements.



\## Workflow

1\. Create a feature branch from `dev`.

2\. Make changes and commit them with meaningful messages.

3\. Push the feature branch to GitHub.

4\. Open a pull request targeting `dev`.

5\. Merge approved changes into `dev`.

6\. Open a pull request from `dev` to `main`.

7\. Tag the completed version.



\## Project Files

\- `README.md`: Project overview and workflow.

\- `.gitignore`: Excludes temporary files and local configuration.

\- `TASKS.md`: Tracks task completion.



\## Learning Outcomes

Practiced Git commands, branches, commits, remote repositories, pull requests, merge workflows, documentation, and version tagging.
